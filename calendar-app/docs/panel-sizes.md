## 二、先更正三个历史错误尺寸（重要）

### 2.1 「1×1 = 346.72×346.72」——那是 SunPanel **配置弹窗里的大预览卡**，不是面板上的卡

v3.15 之前长期以为 1×1 卡片是 346.72px 正方形（并由此推导出 1×2=693.44、2×4=1386.88 等系列）。  
该数值来自 DevTools 检查**微应用配置界面的预览区**——配置弹窗为了预览效果把卡片放得很大。  
**真实面板上的 1×1 只有 76×76 CSS px。** 所有基于 346.72 的推导值（含 audit 的旧「真实尺寸」）全部作废。  
这是「还是有些问题」长期查不明的直接原因之一：按大三倍的空间调字号，真卡上必然溢出/过小。

### 2.2 「1×1 = 113×114」——那是用户屏幕的**物理像素**（dpr≈1.5），不是 CSS 像素

来源：对用户截图（635×174，四张 1×1 卡横排）的像素分析：卡本体 113×114、卡间距 46、容器边距 24，  
验算 `4×113 + 3×46 + 2×24 = 638 ≈ 635` ✓。

按 **dpr = 1.5** 反算 CSS 像素：

| 截图物理值   | ÷1.5 = CSS 值 | headless dpr=1 实测 | 吻合？ |
| ------- | ------------ | ----------------- | --- |
| 113（卡宽） | 75.3         | 76                | ✓   |
| 114（卡高） | 76.0         | 76                | ✓   |
| 46（卡间距） | 30.7         | 30                | ✓   |

三项全部吻合 → **用户机器 dpr≈1.5，CSS 布局与 headless 实测完全一致**，截图只是把每个 CSS 像素  
画成了 1.5 个物理像素。因此：

- 排版/字号按 **CSS px** 设计即可，dpr 只影响「物理呈现粗细」，不改变布局；
- 人眼可读性要看**物理像素**：CSS 3.4px 的字在 dpr=1.5 屏上物理高 5.1px，在 dpr=1 屏上只有 3.4px。

### 2.3 教训（写进团队记忆的三条）

1. **预览弹窗 ≠ 面板**：配置界面的预览卡尺寸是放大的，永远不能当实测值用；
2. **物理像素 ≠ CSS px**：截图量出来的尺寸先问 dpr；
3. **「格数 × 格距」想当然推导不可信**：本次差 3 倍。唯一可信的是 CDP 直连面板量 `getBoundingClientRect`。

### 3.2 规律

- **除 1×FULL 外，全部规格与视口宽度无关**：SunPanel 网格用固定单元  
  —— 单元 76px、单元间距 30px。验算：`76+30+76=182`（1×2）✓、`182+30+182=394`（2×4）✓。
- **1×FULL 宽随视口**，且 ≥1920px 视口封顶 **1878px**（容器 max-width），高恒为 76px（一行高）。  
  视口与 1×FULL 宽的差值：1024→-100、1280→-144、1384→-142、1440→-92、1600→-40、1920→-42。
- 1×1 是正方形（76×76）；1×2/2×1 互为转置；2×2/4×4 正方形；2×4 是 4×4 的右半。

## 四、显示区域（内容盒）推导

### 4.1 宿主 chrome = 26px/轴（CDP 实测盒模型链）

```
.item-card-content          ← 宿主卡，padding:0、overflow:hidden、border-radius:20px、
                               background:rgba(42,42,42,0.42)（真实面板实测）
  └─ :host{display:block; width:100%; height:100%}
       └─ .widget           ← 微应用根，padding:12px + 主题玻璃描边 border:1px
            └─ .card-mode-wrap / .pv-single   ← 内容区（fitFontU 的可用空间）
```

每轴被宿主吃掉 `12+12+1+1 = 26px`。**fitFontU / CONTENT_FIT 的一切计算都必须先扣这 26px。**

### 4.2 各规格内容盒（= 卡尺寸 − 26px/轴）

| 规格                 | 卡片（border-box） | **内容盒（可用空间）** |
| ------------------ | -------------- | ------------- |
| 1×1                | 76×76          | **50×50**     |
| 1×2                | 182×76         | **156×50**    |
| 2×1                | 76×182         | **50×156**    |
| 2×2                | 182×182        | **156×156**   |
| 2×4                | 394×182        | **368×156**   |
| 4×4                | 394×394        | **368×368**   |
| 1×FULL（1384 视口）    | 1242×76        | **1216×50**   |
| 1×FULL（1920 视口，封顶） | 1878×76        | **1852×50**   |

### 4.3 根字号模型（v3.15 定稿，v3.16 沿用）

```
u = min( SINGLE_BASE_PX[size], fitFontU(w-26, h-26, fitFor(content, style, hour12, isZh, opts),
                                        { min: 0.35×base, max: 4×base }) )
```

- **设计基准封顶**：`SINGLE_BASE_PX = {1x1:16, 1x2:17, 2x1:17, 2x2:22, 2x4:26, 4x4:34, 1xfull:18}`  
  ——卡片大于等于设计基准时恒等于出厂设计值（纯公式会把大卡放大到设计值 2 倍集体溢出，已实测否掉）。
- **公式保底**：卡片小于设计基准时按 `fitFor` 实测固有尺寸收缩，clamp 在 `[0.35×base, 4×base]`。
- **1×FULL 例外**（高度驱动）：`baseFull = min(56, max(6, min(h/6.7, w/24)))`。
- `CONTENT_FIT` 是各款式的实测固有 em 宽高（`.tmp/measure-fit315.mjs`，root=100px 超大卡量得），  
  **必须实测回写，禁止拍脑袋**（v3.15 修正 5 处的教训）。

## 五、dpr 换算：用户屏幕上的物理尺寸

用户机器 dpr≈1.5（见 §2.2 验证）。各规格物理尺寸 = CSS × 1.5：

| 规格              | CSS px  | **物理 px（dpr=1.5）** |
| --------------- | ------- | ------------------ |
| 1×1             | 76×76   | **114×114**        |
| 1×2             | 182×76  | **273×114**        |
| 2×1             | 76×182  | **114×273**        |
| 2×2             | 182×182 | **273×273**        |
| 2×4             | 394×182 | **591×273**        |
| 4×4             | 394×394 | **591×591**        |

## 七、v3.16 依据真实尺寸修掉的问题

### 7.1 1×FULL 环形款上下各被裁 4px（真裁切，已修）

- **现象**：`timeDate.ringClock`、`progress.ringProgress` 在 1×FULL 上环形容器 `T-4 / B4` 越界，  
  被宿主 `overflow:hidden` 裁掉（仅在 76px 真实高度下出现；按 346.72 旧基准永远测不到）。
- **根因**：`.pv-single-1xfull .pv-rc-ring / .pv-rp-ring` 写死 `5.2em` 见方。  
  5.2em 是 v3.11 按想当然的「真实卡 1387×347」定的——那正是 §2.1 作废的配置弹窗尺寸。  
  真实 1×FULL 内容区高仅 50px，root 11.3px × 5.2em = 58.8px → 上下各溢 4px。
- **修法**：改为高度驱动 `height:100%; width:auto; aspect-ratio:1/1`（`flex:0 0 auto`）——  
  环永远不超容器，卡片变高时等比放大，横向空间让给时间读数/图例。  
  复跑 audit：**0 裁切**。

### 7.2 audit 假阳性：display:none 容器内的文字被计为「次要注意」（已修）

- `getComputedStyle` 对 `display:none` **容器内**的子元素返回子元素自身的 display 值（不是 none），  
  v3.15 的「跳过 display:none」只查了元素自身 → dayStack@1×1 左列等 21 例「根本没渲染」的文字被误报。
- **修法**：改为沿祖先链判定（`hiddenByAncestor`，查到 `.pv-single` 为止）。  
  修复后真实尺寸 SUB 从 21 → 20（余下 20 个均为真显示，见 §6.1）。
